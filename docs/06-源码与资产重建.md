# 数据丢失后怎样重建

本仓库新增源码来自已成功的本机版本，来源摘要在 `evidence/source-copy-manifest.json`。不是只记录一串指向已丢失目录的路径。

**仍有边界：** 没有在另一台干净 Windows 上验收从下载到 GUI 的全流程；Windows 私有 ABI、系统包、驱动和策略也可能变化。下列构建操作不安装系统组件，只有后续明确的安装步骤会改变系统。

## 一、取得 AI MSIX、RUM 和部署引擎

`tools/acquire/` 保存了固定样本的 WIM 文件索引和解析器。新增 `fetch-resource.py` 只下载明确指定的一个资源，严格检查 HTTP Range、字节数和资源 SHA1；下载完整 MSIX 后还要独立检查签名/Identity。

从仓库根目录，例如：

```powershell
python .\tools\acquire\fetch-resource.py --list
python .\tools\acquire\fetch-resource.py --name onepackage.AggregatedMetadata.cab --out .\downloads\new
python .\tools\acquire\fetch-resource.py --name DesktopDeployment.cab --out .\downloads\new
```

该工具通过固定 UUP dump build 索引刷新微软 CDN 地址，核对 MSU 文件名和尺寸，不把该 build UUID 称为独立 AI UpdateID。旧代资源需同时指定 `--generation old`。索引不含所需版本时，应另找匹配更新，不能拿近似文件顶替。

用 7-Zip 解聚合 CAB、内层产品 RUM 和 DesktopDeployment CAB；按 `evidence/installer-engine-files.json` 找到真实引擎/插件/JSON 配置。不要假设 CAB 解开只有一层。当前工具与插件固定版本必须相配，`953bae...0abef` 是权限窄化所绑定的插件。

RUM 的实体/依赖给出 PayloadName 和版本。用 `fetch-resource.py --name '<索引中的精确名字>'` 逐项取 MSIX，Windows 核验签名和 Identity，再按 [01](01-AI组件-获取与安装-防错流程.md) 放到产品根目录。`evidence/rum-definitions/` 可帮助重建清单，但安装使用原版 CAB。

若本次资源索引不再适用，可重新运行 `msu_range_probe.py`、`wim_metadata_probe.py`、`wim_list_payloads.py` 生成索引；前两者需要工具格式的 MSU 文件列表。不要直接对压缩 WIM 用当前未压缩资源偏移下载。既有 `native-install/tools/onepkg-rum.py`、`auto-fetch-missing.py` 保存较大批量获取的历史实现，运行前检查硬编码 ROOT/代理和清理目录。

## 二、重建 Click to Do GUI 启动器

需要本机可用的 64 位 Python 3.12（含 pythonw）、Frida 17.23.3、PowerShell 7、.NET Framework 自带 C# 编译器。安装依赖到独立环境是可选的，但 pythonw 必须与 Frida 在同一环境；服务身份运行时还需能读取脚本及相关运行库。

```powershell
python -m pip install frida==17.23.3
$pwsh = (Get-Command pwsh.exe).Source
$csc = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc /nologo /platform:x64 /target:exe /reference:System.Web.Extensions.dll `
  /out:work\phase21-host-ifeo\HostStartupDebugger.exe `
  work\phase21-host-ifeo\HostStartupDebugger.cs
if ($LASTEXITCODE) { throw 'Host helper build failed' }
python .\work\phase25-packaged-launcher\build.py $pwsh
```

构建器复制成功脚本到 `outputs/ClickToDo-实验启动器/runtime`，把控制器改为 GUI/隐藏子进程模式，生成 17 文件清单并把其摘要嵌入 GUI EXE。不要把中间源码脚本和打包后的脚本混用；转换是有意的。

先做无 Hook 自检：

```powershell
& '.\outputs\ClickToDo-实验启动器\ClickToDoLauncher.exe' --selfcheck
Get-Content '.\outputs\ClickToDo-实验启动器\selfcheck.json'
```

这不安装模型、不启动 Hook，也不证明 UI 已可用。真正运行还要求原版 CoreAI/Workload 包与脚本固定摘要一致、LNL 产品完整、既有服务端路由补丁匹配。[04](04-ClickToDo-启用与原生入口.md) 给出运行入口和验证边界。

源码中的系统目标路径本来就与包身份/版本绑定，不能任意“改成当前目录”绕过校验；Python 路径由构建器根据实际解释器写入。系统文件变版时需要重新分析。

## 三、从源码重建 Studio 工具包

`studio-cpu/` 保存原版服务包中的自编写代码和管理脚本，**不包含其预编译 EXE 或第三方运行库**。因此 [03](03-WSE-WindowsStudioEffects-攻坚记录.md) 中“工具包已提供”的描述，指原来本机发布包；从 Git 克隆时须先完成本节。

需要 MSVC x64、Windows SDK 10.0.26100.0、OpenVINO 2025.3.0 的 C++ include/libs，以及 Python 3.12.10 嵌入式 x64、Frida 17.23.3 Windows wheel。原 Python/Frida URL 和 SHA256 在 `studio-cpu/asset-provenance.json`，模型准备/桥接使用隔离运行库。

OpenVINO 的 Python wheel 可安装到独立目录供取出 include/libs，先核对确有 `openvino/include` 和 `openvino/libs`；不要给不含 C++ 头/导入库的目录强行套用编译命令。CPU 运行库和模型准备工具都应固定到本次 2025.3.0 代际。

### 3.1 编译自编写程序

```powershell
$vc = 'C:\实际MSVC目录\Tools\MSVC\实际版本'
$ov = 'C:\实际OpenVINO2025.3.0目录'  # 下有 include 和 libs
New-Item -ItemType Directory -Force studio-cpu\payload,studio-cpu\tools | Out-Null
& .\studio-cpu\source\Build.ps1 -OpenVinoRoot $ov -VcToolsRoot $vc
if ($LASTEXITCODE) { throw 'Build failed' }
```

该脚本编译 `payload/StudioCpuService.exe`、`tools/ModelBuilder.exe`，并设置当前 PowerShell 进程的 SDK include/lib 环境。接着编译设备树与采集工具：

```powershell
foreach ($name in 'CameraDurationProbe','SoftwareMepNode','StudioSoftwareHost') {
  & "$vc\bin\Hostx64\x64\cl.exe" /nologo /std:c++17 /EHsc /O2 /MT /DNOMINMAX `
    "studio-cpu\device-host\$name.cpp" "/Fe:studio-cpu\device-host\$name.exe"
  if ($LASTEXITCODE) { throw "Build failed: $name" }
}
Copy-Item studio-cpu\device-host\CameraDurationProbe.exe,studio-cpu\device-host\SoftwareMepNode.exe studio-cpu\payload
```

设备树安装器有自己的 `device-host/binaries.json` 清单。自行编译后的文件可能因编译器不同而不同，应从**自己刚构建的三个工具**重新生成该清单。它与微软驱动哈希不同；不能为了适配未知微软 DLL 而修改后者的白名单。

```powershell
python .\studio-cpu\tools\regenerate-tool-manifest.py
```

### 3.2 补齐隔离运行库和模型壳

- 按 provenance 的摘要下载/解压 Python 到 `studio-cpu/payload/python`，Frida wheel 解到其 `Lib/site-packages`。`python312._pth` 包含 `python312.zip`、`.`、`Lib\site-packages`、`import site`，每项一行。
- 从匹配 OpenVINO libs 复制 `openvino_intel_cpu_plugin.dll`、`openvino_ir_frontend.dll`、`tbb12.dll`、`tbbmalloc.dll`、`tbbbind_2_5.dll` 到 `payload/cpu-runtime`。依赖缺失时补齐同代发行件，不复用别的版本 DLL。
- `tools/ModelBuilder.exe` 同目录需要 `openvino.dll`、IR frontend、TBB 及实际依赖的 Visual C++ x64 运行库。`source/Build.ps1` 只复制其中三项；仍需独立确认插件/VC 运行库能加载。
- 运行 `python studio-cpu/tools/restore-context-templates.py`，从随仓库保存且带摘要的四个小型模型壳重建 `tools/templates/*.onnx`。模型权重来自下一步微软旧包，不在这些壳中。
- 重新生成设备树工具清单后，运行 [03](03-WSE-WindowsStudioEffects-攻坚记录.md) 的 `Prepare.ps1`。它从微软 CDN 下载固定驱动并核验，在目标 CPU 上生成四个真实 CPU 模型及 `payload-sha256.json`。

此后再执行 Setup、GUI 测试、连续录像和真正重启验收。不把离线零输入推理通过当作已验证真实效果。

### 3.3 保留三个原版下载身份

| 用途 | 微软 UpdateID |
|---|---|
| MEP 3.0.8.0 引擎 | `6bb40ca4-7e4c-474a-9bca-db1c53283dc9` |
| 3.0.8.0 相机组件 | `40d5256a-8775-411e-8816-9f4c65596036` |
| 1.0.41.0 旧完整 IR 模型 | `52b47555-d209-4e81-a81f-f3d1b9570497` |

`Prepare.ps1` 保存确切 CDN URL、CAB SHA256 和核心 DLL SHA256。旧包只解资源，不安装。即使 URL 失效也可回微软更新目录按 UpdateID 找同一包，不以近似版本替换。

## 四、如何知道重建真正完成

应分别保留安装日志、无 Hook 的产品枚举、实际模型返回、用户 GUI 反馈、关闭/恢复和真实重启结果。文件存在、程序编译、自检通过、服务 Running 都只是中间检查。

本次文档审核已实际重新编译 Click to Do 的两个 C# 程序、Studio 服务/模型构建器/三个设备树与采集工具，并通过无 Hook 启动器自检。没有为更新文档重装 AI 包、改系统 DLL、注入系统进程、自动重启或打开摄像头。其他机器从零下载到 GUI 的完整复现仍未验收。
