# 从仓库和原始归档重建工具

这份流程不依赖旧聊天、Codex 内置运行时或作者的 Temp 目录。先读 [重装前检查](08-重装前检查与独立复现验收.md)：源码能重建，不代表任意新 Windows 都能使用旧 Hook。

本轮已实际用 Git 文件的新目录完成运行库、工具、四个 CPU 模型及一个九包产品目录重建。没有在干净系统安装驱动/服务或验证 GUI。详细证据见 [冷目录验收记录](10-冷目录重建验收-2026-10-16.md)。

## 0. 准备工具与版本

克隆仓库并进入根目录。需要 Windows x64、普通的 Python 3.12 x64 和 PowerShell 7；构建 Studio 还需 MSVC x64、Windows SDK 10.0.26100.0，以及微软 VC++ x64 运行库。解包 AI 元数据需 7-Zip。

所有命令默认从仓库根目录执行。除明确的安装/规划步骤外，无需管理员。运行库准备、编译、模型准备不会安装服务、注入进程或打开相机。

不要把其他版本系统 DLL 填进旧的哈希白名单。当前固定 Windows 组件清单由 `tools/recovery_preflight.py` 给出。

## 1. 准备独立运行库

```powershell
python .\studio-cpu\Prepare-Runtime.py
```

该脚本只使用 Python 标准库，按 `runtime-lock.json` 的固定 URL、大小和 SHA256 准备 Python 3.12.10、Frida 17.23.3、OpenVINO 2025.3.0。它解出独立 Python、C++ SDK、CPU 插件和必要的 TBB 文件，恢复四个模型壳，并测试 Frida 导入。VC++ 运行库缺失时停止。

离线时，把三个原始 ZIP/wheel 放在一个目录：

```powershell
python .\studio-cpu\Prepare-Runtime.py --offline --cache 'D:\RecoveryInput\runtime'
```

成功应包含 `isolated_frida=passed`、`runtime_preparation=passed`。源码构建后使用 `studio-cpu/payload/python/python.exe`，不依赖全局 pip 环境。这里的轮子保留了 OpenVINO C++ 头和库，不需要凭经验寻找另一套近似 SDK。

## 2. 重建 Studio 工具和模型

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\studio-cpu\Build-All.ps1
```

构建器通过 vswhere 找 MSVC；找不到时明确指定 `-VcToolsRoot 'C:\实际路径\VC\Tools\MSVC\版本'`。它编译服务、ModelBuilder、三个设备树/采集工具，并重算**自编写程序**的清单。不会修改微软驱动哈希。

准备原版驱动与四个模型：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\studio-cpu\Prepare.ps1
```

默认从固定微软 CDN 地址取得三份 CAB。离线可提前把 `mep-3.0.8.cab`、`camera-3.0.8.cab`、`mep-1.0.41.cab` 放到 `studio-cpu/downloads`，仍会校验摘要。也支持 `-DriverDirectory` 和 `-LegacyResourceDll`，见 [03](03-WSE-WindowsStudioEffects-攻坚记录.md)。旧版包只读资源，不安装。

必须在目标 CPU 上生成模型，不能把另一 CPU 的 blob 当通用模型。应看到 face101、matting109、pose113、light132 四行 `cpu_inference=passed`。这是真实离线零输入推理，尚不是实际画面质量测试。

**此时仍未安装 Studio。** 确认普通相机正常、准备好恢复方案后，再按 03 的 Setup、GUI、录像和重启验收步骤操作。

## 3. 重建 Click to Do 启动器

```powershell
$python = (Resolve-Path '.\studio-cpu\payload\python\python.exe').Path
$pwsh = (Get-Command pwsh.exe).Source
$csc = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc /nologo /platform:x64 /target:exe /reference:System.Web.Extensions.dll `
  /out:work\phase21-host-ifeo\HostStartupDebugger.exe `
  work\phase21-host-ifeo\HostStartupDebugger.cs
if ($LASTEXITCODE) { throw 'Host helper build failed' }
& $python .\work\phase25-packaged-launcher\build.py $pwsh
& '.\outputs\ClickToDo-实验启动器\ClickToDoLauncher.exe' --selfcheck
Get-Content '.\outputs\ClickToDo-实验启动器\selfcheck.json'
```

正常自检的 ManifestValid、NoHookStarted、PowerShellExists、PythonWindowlessExists 均为 true。构建器写入实际 Python/PowerShell 路径并固定 17 个文件。移动或删除运行库目录后需要重建，不能只改嵌入摘要的配置。

真正启动还要求匹配的 CoreAI、Workloads DLL、LNL 包、产品关系和路由补丁。见 [04](04-ClickToDo-启用与原生入口.md)，不要把自检当成完整运行验证。

## 4. 从原版资源重建 AI 产品内容

### 4.1 取得部署引擎和产品 RUM

```powershell
python .\tools\acquire\fetch-resource.py --name DesktopDeployment.cab --out .\downloads\ai
python .\tools\acquire\fetch-resource.py --name onepackage.AggregatedMetadata.cab --out .\downloads\ai
python .\tools\extract-product-metadata.py `
  --desktop-cab .\downloads\ai\DesktopDeployment.cab `
  --aggregate-cab .\downloads\ai\onepackage.AggregatedMetadata.cab `
  --output .\recovery-inputs\metadata
```

解包器核对固定 CAB 身份，展开 **DesktopDeployment.cab → Deployment.cab**，按精确摘要收集引擎 DLL，复用仓库固定插件配置，再取得并校验 11 个原版 RUM CAB。只有第一层解包是不够的。`--output` 必须是新目录；7z 不在 PATH 时传 `--sevenzip`。

在线获取依赖 UUP dump 索引和微软 CDN。本轮此环境请求索引曾返回 HTTP 403；这不是“产品不存在”的证据，也说明必须保存离线资产。可直接使用已保存的两个 CAB，不需要联网；若保存的是完整原始 MSU，可给 fetch-resource 传 `--msu-file`，工具会核对完整 MSU 的 SHA256。`--metadata-json` 允许使用另行取得的当前 UUP API 响应，但里面的签名 URL 仍可能过期。

### 4.2 按固定 RUM 取得载荷

```powershell
$product = 'Windows.Workload.ContentExtraction.LNL.amd64'
$plan = python .\tools\prepare-product.py --product $product --plan | ConvertFrom-Json
foreach ($payload in $plan.canonicalPayloads) {
  python .\tools\acquire\fetch-resource.py --name $payload.name --out .\downloads\payloads
  if ($LASTEXITCODE) { throw "Download failed: $($payload.name)" }
}
```

每次只取一个明确资源，校验 HTTP Range/资源 SHA1。工具默认单资源上限 512 MiB；若确认目标确实更大，显式提高 `--max-mib`，不能把人为上限误判为服务器缺包。

若已离线保存 MSIX，直接进入下一步。安装前还应在 Windows 核验 Authenticode；大小/摘要/Identity 校验不等于本次重新验证证书链。

### 4.3 自动组装并验证，不安装

```powershell
python .\tools\prepare-product.py --product $product `
  --engine .\recovery-inputs\metadata\engine `
  --rum ".\recovery-inputs\metadata\rums\$product.rum.json.cab" `
  --payload-dir .\downloads\payloads `
  --output ".\recovery-inputs\products\$product"
python .\native-install\tools\run_install.py attempt-files1 `
  ".\recovery-inputs\products\$product" "$product.rum.json.cab" $product --validate-only
```

这会核对原版 RUM CAB、所有引擎 DLL、配置语义、载荷 SHA256/大小，以及 MSIX 的 Identity 名称/版本/x64 架构。全部通过后才新建产品目录，载荷放根层。故意损坏的文件会被拒绝。

接着按 [01](01-AI组件-获取与安装-防错流程.md)，在管理员进程先 `--plan-only`；明确准备实际部署后才传 `--install`。工具会把原生失败/缺失结果作为非零退出码报告，不以 PowerShell 脚本跑完代替安装成功。

## 5. 重跑不改系统的冷目录测试

```powershell
python .\tests\cold_rebuild.py `
  --destination 'C:\ColdAudit-new' `
  --runtime-cache 'D:\RecoveryInput\runtime' `
  --driver-cabs 'D:\RecoveryInput\studio-cabs' `
  --pwsh (Get-Command pwsh.exe).Source
```

它从 Git HEAD 的实际跟踪文件导出到全新目录，重建并执行四个 CPU 模型、C# 辅助程序及 GUI 自检，记录每步日志。可追加 `--engine`、`--rum-directory`、`--payload-directory` 验证九包产品组装和损坏文件拒绝。维护者未提交审阅时可用 `--include-staged`，结果记录实际 Git tree ID。

测试不会安装产品/服务、修改系统 DLL、注入进程或打开相机。它共享当前 Windows、编译器和证书环境，因此不能称为干净 OS 或另一台电脑的完整验收。
