# 重装前必须保存什么，重装后怎样验收

**结论：文档和源码足以接续研究，但不能单独保证重装后恢复原有效果。** 已知 Hook 绑定特定系统组件，原版模型/驱动/运行库也不在 Git 中。下载入口将来可能失效。重装前至少完成本页的离机保存；如果要保证能回到原有效果，还需要能恢复当前系统版本和组件的系统级备份。

## 1. 三种保存不能混为一谈

| 保存内容 | 能解决什么 | 不能解决什么 |
|---|---|---|
| Git 仓库及提交号 | 研究结论、源码、依赖身份和接续方向 | 不含 Windows/第三方二进制 |
| 离线资产包 | URL 失效后仍能重建运行库、产品目录和 CPU 模型 | 不还原 Windows、ACL、驱动存储和 AppX 数据库 |
| 可恢复的当前系统/安装来源 | 保留当前精确系统环境和持久改动 | 仍需验证恢复和硬件是否相同 |

“备份放在同一台电脑的 Temp/OneDrive 目录”不等于已经离机保存。应确认另一台电脑、外置介质或云端实际已有完整文件，并能独立读取；不要只保留同步占位符。

## 2. 必须保留的资产

- 当前仓库的 Git 提交。可另执行 `git bundle create UnlockCopilotPC.git.bundle --all` 保存 Git 历史，连同本页一起离机。

先确认实际保存的分支里有本页、09、10 和新脚本。审阅 PR 未合并时，默认 main 可能仍是旧版本；不要只记仓库网址。提交全部需要的源码，记录 `git rev-parse HEAD`，并把 Git bundle 保存到被清空的磁盘之外。
- `studio-cpu/runtime-lock.json` 的三个原始归档：Python 嵌入包、Frida wheel、OpenVINO wheel。
- Studio 的三个原始 CAB：`mep-3.0.8.cab`、`camera-3.0.8.cab`、`mep-1.0.41.cab`，摘要在 Prepare.ps1 中。
- AI 产品的**完整 MSIX 精确版本闭包**、原版 RUM CAB，以及部署引擎 DLL/配置。不要只备份 11 个 INVENTORY 文本。若只恢复 Click to Do，优先保留 ContentExtraction.LNL 的 9 个精确载荷。
- Windows 组件身份及用于后续逆向的原件：CoreAI 客户端/DiscoveryOverlay、WindowsAppRuntime.CBS 的 Workloads DLL、Explorer、原版与补丁后的 WSAIFabricHost；相关包的完整安装来源也要保留。
- 服务的 deployment/profile/status、安装前状态、系统 DLL 原件及 ACL 记录。这些用于理解原现场，不能直接导入另一 Windows 版本。

MSVC、Windows SDK 10.0.26100.0、VC++ x64 运行库的安装来源也应保存。普通系统文件的复制不会保留 AppX/CBS 的正式安装关系；保留 DLL 不等于拥有可安装的 CoreAI 包。

## 3. 文件资产包工具

`tools/recovery_bundle.py` 只读明确指定的文件/目录，按 SHA256 去重，复制后复核并在完整结束后标记 complete=true。它不上传数据，不改权限，不安装或还原系统。不要把整个用户目录作为源，避免把个人资料混进去。

以下路径是示例，先替换为实际准备好的资产目录：

```powershell
# 先估算，绝不写文件。这个目标必须在源目录之外。
python .\tools\recovery_bundle.py --plan --bundle 'E:\UnlockCopilotPC-assets' `
  --source 'runtime=C:\RecoveryInput\runtime' `
  --source 'studio-cabs=C:\RecoveryInput\studio-cabs' `
  --source 'ai-products=C:\RecoveryInput\ai-products' `
  --source 'engine=C:\RecoveryInput\engine' `
  --source 'system-reference=C:\RecoveryInput\system-reference'
# 核对大小和路径后，把 --plan 改成 --export；要求目标目录尚不存在。
```

复制到离机介质后，在该介质上验证：

源较多时可用 `--sources-json sources.json` 代替多组 `--source`，内容为 `{"runtime":"C:\\实际缓存目录","engine":"C:\\实际引擎目录"}`。该文件记录的是当前电脑路径，应在重装前导出资产；只保存来源清单不会保存原始文件。

```powershell
python .\tools\recovery_bundle.py --verify --bundle 'E:\UnlockCopilotPC-assets'
# 重装后只恢复到新的普通资料目录，不写 Windows：
python .\tools\recovery_bundle.py --restore --bundle 'E:\UnlockCopilotPC-assets' --destination 'C:\RecoveryInput-restored'
```

工具是文件资料备份，不保留 ACL，也不是系统镜像。复制期间文件变化、缺文件或摘要不符会停止；出现失败时不能把 incomplete 的目录当成成功备份。请先用小型目录试一次导出、验证和恢复，再备份大体积资产。

## 4. 重装后先判断能不能用旧 Hook

```powershell
python .\tools\recovery_preflight.py --output '.\target-compatibility.json'
```

这是只读哈希核对。未安装模型包时相应路径不存在是正常的前置缺口，不要删除校验。它检查成功也不证明产品关系或界面已就绪。

若 CoreAI、DiscoveryOverlay、Workloads DLL、Explorer 等不是文档固定摘要，**停止使用旧偏移**。两条合理路线：恢复到匹配的系统/组件，或者针对新版重新分析并更新 Hook。本仓库尚未提供从任意最新版 Windows 自动取得和安装旧版全部系统组件的方案。

## 5. 哪些脚本现在应当使用

| 入口 | 是否改变系统 | 用途 |
|---|---|---|
| `tools/recovery_preflight.py` | 否 | 版本检查 |
| `tools/prepare-product.py` | 否，仅新建资料目录 | 按固定 RUM 校验/组装产品 |
| `run_install.py --validate-only` | 否 | 校验内容，不运行部署 DLL/Frida |
| `run_install.py --plan-only` | 运行管理员原版部署规划，不调用 Install | 确认原生下载请求数 |
| `run_install.py --install` | 是 | 实际单产品部署，需明确指定 |
| `studio-cpu/Prepare-Runtime.py`、Build-All.ps1、Prepare.ps1 | 否，仅文件下载/编译/CPU 推理 | 重建工具与模型 |
| `studio-cpu/Setup.ps1` | 是 | 安装驱动/服务和摄像头关联 |
| ClickToDoLauncher 普通启动 | 是，临时注册及进程 Hook | 实际功能运行 |
| `tests/cold_rebuild.py` | 不安装/Hook/打开相机 | 从 Git 文件和指定归档重建并真实离线推理 |

`archive/`、旧 `wse/` 和其他历史下载探针保留研究价值，但不要逐个执行来“恢复环境”。

## 6. 复现验收必须分层

1. 源码能编译、运行库能导入、文件摘要匹配。
2. 四个 Studio CPU 模型在本机执行真实推理；AI 产品根目录完整，错误文件能被拒绝。
3. 原版产品 Install 成功且无 Hook 新进程能枚举产品。
4. 原版 Click to Do/Studio GUI 可操作、真实画面正确。
5. 关闭后能恢复普通相机/搜索；服务/工作进程重启后恢复。
6. 真正整机重启后再验收，其他硬件另做一次。

第 1–2 层的冷目录测试不是第 3–6 层的干净系统验收。新修的脚本在未重新安装验证前，不能把旧版本现场成功自动记到新版本名下。
