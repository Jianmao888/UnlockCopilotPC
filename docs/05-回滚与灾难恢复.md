# 停用、恢复与备份

先区分临时进程 Hook、持久服务和磁盘补丁。退出一个 Hook 不会自动卸载产品，也不会恢复此前修改过的系统 DLL。本文是恢复顺序，不是要求一次执行全部卸载。

## Click to Do 正常关闭

```powershell
& '.\outputs\ClickToDo-实验启动器\ClickToDoLauncher.exe' --stop
```

等待几秒，再读 `outputs/ClickToDo-实验启动器/runtime/phase24-manual-test/session-state.json`：应为 Stopped，`NativeCleanup.SearchRestored=true`、`IfeoAbsent=true`。最近成功测试还记录了包调试 Disable HRESULT=0。证据不在时就实际核对，不能直接照抄历史 PID。

正常清理会先注销 CTD 的 Win＋Q、恢复 Explorer 搜索，再撤销包调试和精确宿主 IFEO。`--stop` 在本机是隐藏 GUI 入口。强杀后台可能跳过清理；不要用“杀所有 python/pwsh”代替。

如遇异常残留，先保存 `session-state.json`、对应 `*-recovery.json` 和日志。检查：

```powershell
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\WorkloadsSessionHost.exe\CodexAIResearch' -ErrorAction SilentlyContinue
```

仅在 Debugger 和 FilterFullPath 确认属于本研究时，撤销该子项。不要递归删除整个 IFEO 父键。包调试用打包后的 `runtime/phase19-clicktodo/package-debugging.ps1 -Action Disable` 撤销自己的设置。

Win＋Q 归还失败时，先退出本次 CTD 会话再重启 Explorer，可让搜索在新 UI 线程重新注册；重启 Explorer 会打断桌面/任务栏，因此是故障恢复操作，不是常规启动步骤。未证明这能解决所有热键冲突。

## Studio 先恢复普通相机

先在 Studio 面板关闭效果，关闭相机/会议应用，再停用 CPU 桥接。否则仍开启的原版引擎会回到 NPU 路径，可能再次无法出帧。

已安装的桥接可通过自己的脚本卸载，保留文件和诊断：

```powershell
& 'C:\ProgramData\CodexStudioCpuBridge\Uninstall-Bridge.ps1'
```

新机器上由本工具新建的完整设备树，可用 `studio-cpu/Uninstall-All.ps1` 撤销。当前研究机的 V2 服务是此前已有状态，脚本会保护它，不能当成干净新装状态强行删除。

若相机打不开，按现场设备清单找到**本研究的效果相机节点**，可临时禁用它以排除效果管线；不要禁用物理摄像头或照抄其他机器的实例号。旧机节点 `ROOT\MEP_CAM_VEN_8086_DEV_B03E\0000` 只是历史标识，新方案使用 SWD 主节点及 DRIVERENUM 子节点。

相机关联是所选 VIDEO_CAMERA 接口的 `FSMEnableMsEffects`。从安装状态记录恢复原值；原本不存在时需删除本工具新增的值。`reg import` 只合并，**不会自动删除备份中原本没有的值**。

不按 `oem42.inf/oem61.inf/...` 固定编号卸载驱动：这些编号因机器和安装顺序而变。用 PnPUtil 的实际清单核对原始 INF、提供者、版本、被哪些设备使用，再决定是否卸载。共享微软驱动一般可保留。

## WSAIFabricHost.dll 持久补丁

本机原备份路径为 `C:\ProgramData\AiLab\WSAIFabricHost.dll.orig`，另有研究目录原件。先核对原件 SHA256 为：

`ea8f782b722161a15c2cc5bcff1407d4844aa972af4bb7bf45b5c0751e486170`。

只有与当前系统版本匹配的原件才能恢复。结束本次 Hook 和模型调用，在正常管理员/系统维护方式下恢复文件及原 ACL，再重启 WSAIFabricSvc 或按需要重启系统；不要覆盖成另一 Windows 版本的 DLL。文件替换可能受权限、映像加载和系统修复机制影响，不能写成任何环境下“一条复制命令即可”。

旧 `patch-fabric.py` 仅制作候选副本。没有备份时先从匹配系统/更新恢复原文件，不猜字节，不假设补丁后的数字能反推所有变化。

## AI 产品与包

先做只读组件枚举和产品关系查询。不要为“刷新状态”卸载所有 WindowsWorkload 包，不直接编辑 StateRepository 或删除整库。

AppX staged、当前用户注册、provisioning 和 UUP 产品关系分别维护；Remove-AppxProvisionedPackage 不等于把所有状态都清理干净。尚未提供经验证、能逐一卸载所有实验产品并保留共享依赖的通用回滚器；需要卸载时按实际产品的原版部署接口另做方案。

`takeown/icacls` 管理文件权限，不能用它们取得注册表键所有权。不能为删除测试项而扩大整棵 AppRepository 或 HKLM 的权限。

## 灾难恢复应保留什么

Git 仓库保存源码、原版载荷定位、摘要和最小历史证据。另行离线保存：合法取得的原版 MSIX/RUM CAB/引擎、原系统 DLL 及 ACL、每次安装前状态、服务部署记录和匹配系统恢复介质。

数据库 `.srd` 及 WAL 的普通文件副本是分析材料，不是可任意写回另一系统的回滚镜像。需要一致快照时使用 SQLite 事务备份或可靠系统快照。不要把包数据库当作本项目配置文件覆盖恢复。

重装后按 [06](06-源码与资产重建.md) 重建，逐层验证：普通相机 → 产品登记 → OCR → Click to Do/Studio → 对应 GUI → 真正重启。不能仅凭历史文件存在就恢复“已验收”状态。
