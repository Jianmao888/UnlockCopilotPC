# 从这里接续研究

核对日期：2026-10-16。本机是 Xiaomi Book Pro 16 2022，i7-1260P，无 NPU；已验证系统为 Windows 11 x64 build 26300.9550。版本和路径是实验条件，不是对其他系统的兼容承诺。

## 我们已经做到什么

| 能力 | 已有证据 | 边界 |
|---|---|---|
| AI 产品安装 | 微软原版 UALite/MSIX 插件完成部署和产品登记，独立组件枚举成功 | 零散 MSIX 安装不等于产品登记 |
| OCR | LNL 路线真实识别成功 | 不证明所有调用应用的 GetReadyState 都为 Ready |
| 语义搜索相关模型/API | 另一轮 Gallery 测试报告成功 | 不等于 Windows 全系统搜索功能已完整启用 |
| Click to Do | 原版覆盖层识别、选择成功；用户重启后反馈复制和打开可用 | 不含 Recall、改写、摘要等全部 AI 操作 |
| 原生 Win＋Q | 用户实按后能正常打开并选择；启动器已自动协调注册 | 先运行一次启动器，会话约 15 分钟；未设置登录自启 |
| Win＋鼠标单击 | 能触发原版客户端，但界面短暂出现后消失 | 未解决，尚未证实是进程崩溃 |
| 开始菜单 | 已添加“单击以执行（实验版）”启动器入口 | 原版应用已注册，其原始条目显示条件仍未修好 |
| Studio 自动取景、背景模糊 | 用户确认真实画面效果，模型真实 CPU 推理及连续录像通过 | 仅此实机；眼神交流等未完成 |
| Studio 服务固化 | 两个自启服务已安装；服务重启及工作进程异常恢复通过 | 整机重启后的效果验收没有完整记录 |

“Ready”“能创建模型会话”“推理返回成功”“界面功能正常”是四种不同结果，不能相互代替。

## 数据丢失后先做什么

1. 克隆本仓库，先读 [资产重建](06-源码与资产重建.md)。仓库保存源码、元数据和部分小型证据，**不包含现成的 Windows DLL、MSIX、驱动 CAB、Python 运行库和编译好的模型**。
2. 按 [安装流程](01-AI组件-获取与安装-防错流程.md) 重新取得匹配的 RUM、部署引擎和精确版本载荷；先读状态，再决定是否安装。
3. 要恢复 Click to Do，读 [Click to Do](04-ClickToDo-启用与原生入口.md)，重建辅助程序和启动器。不要先试全局 Ready 补丁。
4. 要恢复 Studio，读 [Studio 指南](03-WSE-WindowsStudioEffects-攻坚记录.md)，同时按资产重建文档补齐运行库和自编译工具。不要重新采用旧的三个并列 ROOT 节点方案。
5. 先验证已有功能，再从下节挑一项继续。没有现场证据前，不把重建结果写成成功。

## 尚未解决的问题

优先追查 Win＋单击：在同一已预热的原版客户端内，对照成功 Win＋Q，记录手势入口的参数、窗口激活/失焦、取消和隐藏调用，找到最早差异。旧观察只证明经过 dispatch / window-activation，不足以归因。

其次是 Studio 实际整机重启后的效果、其他摄像头/CPU、长期稳定性，以及资源 119 的完整 CPU 模型来源。先前只有设备持久记录、却没有开机重新枚举的方案在真实重启后失效；不能再把服务重启测试当整机重启验收。

仍未找到让所有应用统一返回 Ready 的修改点；应用可能携带各自的 Windows App SDK 实现。服务器独立 AI UpdateID、通用产品请求为什么失败、HybridCompute 所需组件的完整获取，也不能算已经解决。

## 现场状态与历史数字

2026-10-15 的另一轮记录包含“58 个包”“13 行产品记录”，四个 LNL 产品的关系数为 9 / 20 / 9 / 14。这些是**历史快照**，不是本日重新点验结果，也不是 13 个不同的正式产品；存在同名旧记录和测试产品。见 [产品清单](02-AI组件-产品与载荷清单.md)。

2026-10-16 的只读检查发现两个 Studio 服务均运行，CPU 桥接 active=true，但 rebootVerified=false，且该状态的 inference_counts 为空。它证明服务和挂接状态，不证明当时开启相机后的效果。Click to Do 最后一轮测试已正常清理，搜索热键已归还，临时 IFEO 已撤销。

## 研究纪律

- 先看源码和已保存证据，不重复运行安装、相机采集或注入来“检查文档”。
- 不直接编辑 StateRepository，不凭缺少一条数据库查询结果就卸载共享包。
- 不把“没下载到”写成“微软从未发布”；不把一个 HRESULT 写成唯一根因。
- 不重新加入已导致原版客户端异常展开崩溃的 RaiseException / RtlRaiseException 观察 Hook。
- 所有地址都绑定文件哈希。更新后先重新分析，不能只更新白名单摘要继续使用旧偏移。
